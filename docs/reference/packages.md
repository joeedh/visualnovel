# Packages and layering

Describes what each package in the monorepo is responsible for, and the rules that keep the graph
acyclic. The dependency graph itself (the ASCII layering diagram) is in
[`../../CLAUDE.md`](../../CLAUDE.md#package-layering). The layering is enforced by
`eslint-plugin-boundaries` + `import/no-cycle`, configured in `eslint.config.mjs`; adding a package
means adding it to four lists — see
[`../guides/toolchain.md`](../guides/toolchain.md#adding-a-package).

## The layering rules

The pipeline spine (`pipeline → scheduler → cli`) and the authoring branch (`authoring →
authoring-app`) are disjoint below `@vn/store`/`@vn/providers`. `@vn/authoring` reuses the
input-side packages (types, util, config, parse, model, store, providers, git) but must never
import `@vn/pipeline` or `@vn/scheduler`. `eslint-plugin-boundaries` enforces this.

Four leaves share that same constrained allow-list, and each has its own reason:

- **`@vn/export`** projects the manifest into `story.play.json`. It is also forbidden from using
  the generative pipeline or the scheduler.
- **`@vn/scriptedit`** holds the scene-edit rules and write path. The desktop app's `story.*`
  commands and `vnauthor` both run the same rules, so those rules cannot live in either
  ([`../plans/archive/INDEX.md#scene-edit-package`](../plans/archive/INDEX.md#scene-edit-package)).
- **`@vn/bible`** is the third package. Both the agent and the desktop app search the story
  bible, so the ranking policy belongs to neither ([`story-bible.md`](story-bible.md)).
- **`@vn/artgen`** is the fourth package, and the one with the deepest dependencies. It holds
  prompt composition (moved out of `@vn/pipeline`, which re-exports it) and on-demand generation,
  so it imports `providers` and `taskgraph` as well. `@vn/authoring` importing it is not a way
  around the pipeline ban, because the boundaries rule applies per import statement and is not
  transitive
  ([`../plans/archive/INDEX.md#on-demand-concept-images`](../plans/archive/INDEX.md#on-demand-concept-images)).

Two packages sit outside the graph entirely, and neither is drawn in the diagram. `@vn/debug2d`
imports nothing from `packages/` and is imported only by the desktop renderer's dev-only debug glue
(`debug2d: []` in `eslint.config.mjs`), so it stays strippable from production builds.
`@vn/testkit` has the opposite constraint: it may import every layer, and nothing may import it —
see [`../guides/testkit.md`](../guides/testkit.md).

## What each package is responsible for

| Package             | Responsibility                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `@vn/types`         | All entity/task/provider types + **zod schemas** for files and structured LLM output. Single source of truth for shapes. Depends only on `zod`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `@vn/util`          | `sha256`/canonical-JSON hashing, atomic fs writes, JSONL append/read, structured logger, bounded async `pool`, `retry`, typed errors.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `@vn/config`        | Load/validate `project.yaml`; resolve API keys from env then secret files. **Never logs key values**; errors name only the source.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `@vn/parse`         | Fountain parser + note markers: `[[choice: … -> id]]` / `[[scene: id]]` / `[[next: id]]` for branching, `[[outfit: aiko=track]]` for scene-level wardrobe, `[[line: L4]]` / `[[nextline: 12]]` for allocated line ids; markdown front-matter, including the byte-exact `splitFrontMatter` a prose patcher splices under. Also the `LoadedInputs` / `SceneChunkDoc` shapes the reader and the model builder both name. Pure, no I/O policy. Shared with the authoring agent.                                                                                                                                                                         |
| `@vn/model`         | Build + validate the in-memory project model (refs resolve, every `goto` targets a real scene, reachability/dead-scene detection); emit `story.graph.mmd`. Also the **writers**: `sceneToFountain` (lossless — `parse(write(scene)) ≡ scene`), the surgical `branchpatch`/`lineids` patchers, the `*ToDoc` serializers, and the two pure halves of import/export: `sceneChunksFromScript` and `scriptFromScenes`. And `outfitFor`/`outfitText` — the outfit inheritance chain, written down once.                                                                                                                                                   |
| `@vn/store`         | The only reader of a project's files: `loadInputs` (authored `scenes/<id>.md` chunks; entities discovered by `type:` tag across three surfaces; a leftover `screenplay/` is reported by `findScreenplay`, never read), the content-addressed asset store across **two roots** — base art in `assets/` and shot frames in `build/assets/`, each with its own `manifest.json`, behind one `AssetStore` facade (`AssetRoot` is one root; `baseAssetsOf` describes the base one alone) — and the `work/` tree — including `shots/<sceneId>.json`, whose reader/writer is the only place the flat in-memory `Shot` and its nested `shotData` are mapped. |
| `@vn/export`        | Leaf projector: `buildPlayable(model, store)` → `story.play.json` (flattened ordered beats + branch edges; asset refs by `{hash,ext}`). Input-side only — forbidden from `pipeline`/`scheduler` (boundaries-enforced).                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `@vn/scriptedit`    | The scene-edit rules (`lineops`: nine pure decisions over a scene set; `shotorder`: the tenth, which reorders a shot by moving the lines it covers; `outfits`: what a character wears, at either level) + their consequences (`shotfallout`) + the write paths (`sourcesOf` → `planSceneEdit` → `applyScenePlan` for prose, `planMarkerEdit` → `applyMarkerPlan` for `[[…]]` markers). Shared by the desktop's `story.*` commands and `vnauthor`, so one authorial act has one answer. **Two entries**: the barrel is pure and browser-safe (the renderer runs `moveLine` to preview a drag); the filesystem half is `@vn/scriptedit/write`.        |
| `@vn/artgen`        | Art generation policy, shared by the pipeline, the desktop and `vnauthor`. **Prompt composition** — every builder a planned image derives from, moved here so the input side can reach it — plus **on-demand generation**: `generateConcept` (one sentence → one `concept` asset, bound to what it sketches, planned by nothing) and `promoteConcept` (a sketch becomes the location plate the planner would have rendered). Also **art direction** — the five art-notes rungs (`rungsFor`, `setArtNotes`) that both the desktop's `art.setNotes` and `vnauthor`'s `set_art_notes` write through — and the **vision read-back**, `describeAsset` (bytes + a question → an answer), which is how an agent revises against the picture that exists rather than the prompt it wrote. Node-side; never in `apps/desktop/src/shared/`.                                                                                                                                                                        |
| `@vn/gengraph`      | The node graph an asset is generated by, over path.ux's own graph module (reached through the `pathux-graph` and `pathux-toolprop` aliases, never through `pathux`). Holds the node-type registry (a path.ux `Node` subclass plus a spec naming whether the type spends money and which prop carries its slot), the graph file reader and writer with nstructjs `validateJSON` at the boundary, the semantic pass over a loaded graph (props against the spec, socket compatibility, an Output node's slot), the run journal's record types and its replay, the DSL an agent reads and rewrites a whole graph through (`graphToDSL`, `applyGraphDSL`, which diffs by node id so a surviving node keeps its layout and its journal), the cost model (`estimateGraph` over a topological walk, with the refine tail counted `max_refine_attempts` times) and the shipped price table it is priced against (`priceEstimate`, which names a model no table covers instead of counting it as free), the twelve built-in node types with the three socket types they wire together (`registerGenNodes` declares the types, `registerGenRuntimes` binds their work as well), `GenServices` — the capability interface a node runtime sees, which the pipeline and the desktop app each implement — and the node key (`nodekey.ts`: `nodeKey`, `resolveNodeKey`, `flattenNodes`, `instancedRefs`), the id chain from the root that names a node inside a group instance, which the hashes, the journal, the executor and every command's `node` prop are keyed by. **Two entries**: the barrel reaches no `fs` of its own and no DOM, and the derived prompt arrives as a node input rather than as a service; `@vn/gengraph/state` holds what reaches the project's `vngen/state/` tree (the graph and journal paths, `nodeHash` and `graphHashes`, the journal's file half, the content-addressed blob store, and `graphDrift`) and the graph documents under `vngen/work/graphs/` (`readGraphDoc`/`writeGraphDoc`, the group library under `lib/` through `readGroupDef`/`writeGroupDef`/`readGroupLibrary`, and `bindGroupLibrary`, which points a graph's `groupLoader` at it). The whole feature is described in [`gen-graphs.md`](gen-graphs.md); plans: [`../plans/node-based-asset-generation.md`](../plans/node-based-asset-generation.md), [`../plans/archive/group-nodes-in-the-gen-graph-editor.md`](../plans/archive/group-nodes-in-the-gen-graph-editor.md).                                                                                                                                                                        |
| `@vn/bible`         | Retrieval over the story bible (`wiki/`): index a markdown tree, `query(text, {limit, budget}) → ranked excerpts`. **No whole-file API** — that absence is what keeps the bible out of the context window. Grep ranking today, swappable for embeddings behind the same function. See [`story-bible.md`](story-bible.md).                                                                                                                                                                                                                                                                                                                          |
| `@vn/commands`      | The command framework: typed prop specs, registry, `namespace.command(a='x' b=1)` DSL, execution stack with git provenance, JSON catalog projection, the `ContentStore` and `UndoJournal` behind opt-in undo/redo, and the `Committer` behind opt-in commit-on-save. Domain-agnostic — the commands themselves are defined by the host app. **Two entries**: the barrel is browser-safe, since the renderer imports the command record and the DSL; the snapshot half reads and writes files and is `@vn/commands/snapshot`. See [`command-system.md`](command-system.md).                                                                                                                                                                                                                                                       |
| `@vn/debug2d`       | Source-agnostic 2D graphics debugging: fragment IR, space registry, DOM adapter (stacking-order z with culprit retention), query engine, `explainPick` rejection logs. **Zero deps** — it duplicates ~50 lines of `Rect`/`Mat3` helpers in `geom.ts`, and that is deliberate: do not "deduplicate" them. Outside the layering graph; dev-only in the desktop renderer, so `vite build` drops it. Usage: [`../guides/debugGuide.md`](../guides/debugGuide.md).                                                                                                                                                                                                          |
| `@vn/taskgraph`     | `Task` node model, content-addressed dedupe key, DAG + topological order, `tasks.jsonl` status log, staleness/resume.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `@vn/providers`     | Provider-agnostic `ImageProvider` / `VisionReviewer` / `TextLLM` over a low-level `ChatBackend`/`ImageBackend` seam. Gemini + Claude backends (lazy-imported). Structured-output enforcement + retry live here, as does the record/replay `AssetCache` + `CachedImageBackend`. `chatConversation` is the conversation-shaped seam the authoring agent sends over; `buildConvoRequest` is the one place the four `cache_control` breakpoints are placed and deferred tools are flagged, and `TokenUsage` splits the input into what was read from the cache and what was written to it.                                                                                                                                                                                                                                                                                                                                                                      |
| `@vn/pipeline`      | The phases P1–P7 as deterministic prompt builders, an incremental task **planner**, per-kind **runners**, the approval **gate**, and a cost-preview facade. Also the host's half of a generation graph: `createGenServices` wires `@vn/gengraph`'s capability interface to this project's providers, asset store and keys, and `graphrun.ts` indexes the loaded graphs by the slot each active output claims, seeds a bound graph from the task, and writes what it terminates on through the same `deps.store.write` the unbound runners use. A slot no graph claims runs the code it ran before graphs existed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `@vn/scheduler`     | Plan → run-ready-wave → replan loop under a concurrency cap; gates as barriers; crash-safe via the status log; dry-run cost preview.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `@vn/cli`           | `vngen run \| approve \| status \| graph \| export \| cost \| import \| screenplay`. Bundled by esbuild. See [`../guides/cli.md`](../guides/cli.md).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `@vn/git`           | Thin promisified wrapper over the `git` CLI (`isRepo`/`status`/`commit`/`log`/`show`/`diff`/`revert`/`restore`/`init`/`config`), plus tree plumbing (`writeTree`/`commitTree`/`treeOf`/`applyTree`/`updateRef`/`deleteRef`/`listRefs`, all against a scratch index so HEAD and the real index are untouched) that undo used to rest on and nothing calls today, and `RepoResolver`, which answers which repo owns a path (`git rev-parse --show-toplevel`, cached) so a project spanning several repos needs no new plumbing. Spawns via `node:child_process`, never interactive. **No policy** — gating lives in the agent.                        |
| `@vn/authoring`     | The `vnauthor` agent core: workspace index, `AICONTEXT.md` loader + the generated project map (`AICONTEXT.generated.md`), tool registry, ReAct/native agent loop (native by default, over `chatConversation`), plan-mode + permission gate, skills. The tool catalog it sends is byte-stable for a session — six schemas loaded, the rest deferred — and anything that changes mid-conversation is appended as a `system` message rather than edited into the prompt prefix. Input-side only; cannot import pipeline/scheduler. See [`vnauthor.md`](vnauthor.md).                                                                                                                                                                                                                                                                                                                                                        |
| `@vn/authoring-app` | `vnauthor` interactive REPL: renders plan diffs, prompts for approval, streams turns, `/status` and `/skills` commands. Bundled by esbuild like `vngen`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `@vn/testkit`       | **Test-only** fixtures: `makeProject` (real inputs on disk → real run with mock providers), `synthProject` (deterministic scale), `SCRIPTS`, in-memory entity factories, and the recorded-art corpus at `assets/`. Imports every layer; nothing may import it. See [`../guides/testkit.md`](../guides/testkit.md).                                                                                                                                                                                                                                                                                                                                                     |
