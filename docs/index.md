Reference material for the VN Generator monorepo. For the working map of the code itself
(package layering, the invariants in brief), see [`../CLAUDE.md`](../CLAUDE.md); each area's
full write-up is below. CLAUDE.md keeps the git-history and tooltip rules in hand; the rest of
how this repo is written is [`conventions.md`](conventions.md). For how to debug the repo
(state files, CDP, the 2D debug surface, known traps), see [`debugGuide.md`](debugGuide.md).

Implementation plans live separately in [`plans/`](plans); [`plans/index.md`](plans/index.md)
lists all of them with their build status.

| [`research/agent-access-to-the-ux-command-system.md`](research/agent-access-to-the-ux-command-system.md) | Whether `vnauthor` should reach the desktop's 108 registered commands directly, weighed against the seam that exists today (shared *decisions* — `@vn/scriptedit`, `@vn/model` — with separate transports): what a full bridge buys (one audit log, one undo history, `stack.check` as a free planning oracle, the agent opening the pane it is talking about) against what it costs (131 KB of catalog against six cached tool schemas, two names for every prose act, a command sized for a hand rather than for a drafting model, and a hand-kept deny list of exactly the shape the anchors plan exists to avoid) — plus four invariants a naive bridge breaks on contact, the first being that `agent.setMode` is a registered command and plan mode is a guarantee only because the model cannot reach it. | [`research/pressure-test-user-authored-macros.md`](research/pressure-test-user-authored-macros.md) | An adversarial read of [`research/user-authored-macros-and-custom-actions.md`](research/user-authored-macros-and-custom-actions.md) against the code: a `CommandRecord`'s `invocation` is built from *digested* props, so "recording a macro is filtering the history" is impossible for every `digest` or `secret` prop and the journal's own doc says a digested invocation is not re-executable; the report's worked example `prompt.repin(hash=$1 …)` is rejected outright by `parseCommand`, because `$` is not a legal value start and any interpolation form stops a step from being the copy-pasteable invocation the format was chosen for; "every one that spends money, computed from the catalog" is not computable at all, since nothing in `Command` records cost and `pipeline.run` — the largest spender — is deliberately not `confirm` while `asset.upload` is; preview-as-bracket reverts the base `assets/` root that `art.generate` was declared un-undoable to protect and poisons every per-command undo point taken inside it; and preview cannot force mock, because `WorkspaceSession.mock` is `readonly` and the money commands have no `mock` prop — against a placement design, a root-only verdict and a menu look-up-by-id argument that all hold, plus `menuFor` and `lineMenu` already being the named builders stage 1 proposed to create.
