Reference material for the VN Generator monorepo. For the working map of the code itself
(package layering, the invariants in brief), see [`../CLAUDE.md`](../CLAUDE.md); each area's
full write-up is below. CLAUDE.md keeps the git-history and tooltip rules in hand; the rest of
how this repo is written is [`reference/conventions.md`](reference/conventions.md). For how to debug the repo
(state files, CDP, the 2D debug surface, known traps), see [`guides/debugGuide.md`](guides/debugGuide.md).

Implementation plans live separately in [`plans/`](plans); [`plans/index.md`](plans/index.md)
lists all of them with their build status, and a shipped plan's file sits in
[`plans/archive/`](plans/archive).

The directories say what kind of document a file is: [`guides/`](guides) is how to *do*
something (run, debug, get a key), [`reference/`](reference) is how a shipped part of the
system *works*, [`history/`](history) is the reports and surveys that shaped the design and
are now static, and [`research/`](research) is exploratory work that may never ship.

Concludes that the offline half is already built and the live half is worth a run per model release rather than a standing suite. |
| [`research/shot-framing-systems.md`](research/shot-framing-systems.md) | A build-oriented survey of how generative systems produce a *specifically framed* shot, staged as prompt → layout → camera → conditioning → validation, with three costed architectures and the evidence for each. The finding that shapes it: the validation half is essentially unbuilt — every published closed-loop image system verifies object presence, count, attribute binding or pairwise spatial relations, and **none** verifies shot scale, crop, headroom or camera height, while the best of 24 VLMs scores 55.2% on composition, which is why the systems that work separate *measurement* (a detector) from *judgement* (a language model). The second finding is that the intuitive case for 3D proxy geometry does not hold up: the authors' own head-to-head table gives 3D boxes 24.3% object accuracy against a 2D layout baseline's 48.2%, the 3D win arrives only with extra machinery, its two baselines swap places depending on which placement metric you read, and one author co-writes both compared methods plus the depth estimator underneath them — while an independent group's CVPR 2026 comparison puts a *training-free 2D* method above both 3D-proxy systems on depth ordering, the one metric a 3D proxy is supposed to own. Of the four intuitive arguments for going 3D, occlusion ordering and vanishing-point consistency turn out to be measured repeatedly, scene reuse is measured by proxy, and only **character scale across shots** is genuinely unquantified — which is the one that matters most here, because the story-visualization benchmarks crop characters to compare identity and then discard the bounding boxes, measuring *who* and never *how big*. Also: why ControlNet does not transfer to DiT models and the four mechanisms that replaced it, control strength as three orthogonal axes (of which denoising *time* is the one that matters for composition), the shot-scale and camera-angle classifiers that make framing checkable — ~94% and >95% on live-action, but 0.80 F1 for scale and only 0.61/0.68 for angle and level on animation, so scale survives the stylised-art domain gap and camera geometry does not, which is what decides which framing properties a checker can police; why every camp converges on a small discrete shot vocabulary, proxy leakage degrading prompt adherence rather than only realism, the inference-infrastructure finding that one question — control map with a conditioning scale, or merely a reference image? — partitions the market far more sharply than price does, since almost every 2026 image API is the second thing, only fal and Stability expose a strength dial (and Stability has no pose endpoint at all), OpenRouter routes image generation but cannot route structural control because none of its upstreams have it, and the FLUX [dev] licence covers every control model anyone would self-host while leaving the outputs unrestricted, so calling a host is the licensed route and downloading the same weights is not — with cold start left as the largest unmodelled cost term, no third-party measurement existing for a 10–25 GB model and RunPod's headline sub-200 ms figure measuring a retained warm worker rather than a cold weight load; and the absence of any validated whole-character consistency metric — DINO agrees with human preference 50.72% of the time and CIDS says of itself that it is face-centric. Closes on this repo: `makeShotRunner` already closes a loop and `shotSpec` already carries `framing` to every reviewer, so the gap is one geometric measurement function rather than an architecture, and the `framing` enum is load-bearing for the task-hash dedup as well as for authoring. |
